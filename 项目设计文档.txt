《易选好寓》项目设计文档
版本：V1.0
日期：2025-11-03

1. 文档概述
1.1 编制目的
    本文档提供易选好寓项目的总体设计说明，描述系统架构、模块职责、数据设计、接口协议以及部署策略，指导开发、测试与运维活动。
1.2 适用范围
    适用于参与易选好寓项目的产品、架构、后端/前端开发、测试、运维人员。
1.3 参考资料
    - 需求规格说明书
    - 源代码仓库（common、model、web 子模块）
    - Spring Boot、MyBatis-Plus、Knife4j、Spring AI 等官方文档

2. 系统架构概述
2.1 技术栈
    - 后端：Spring Boot 3.3.8、Spring Web、Spring Data Redis、Spring AI、MyBatis-Plus 3.5.6
    - 数据库：MySQL 8.x
    - 缓存：Redis 6.x
    - 对象存储：MinIO（S3 兼容）
    - 前端：Vue（租客端、管理端分别构建）
    - API 文档：Knife4j / OpenAPI 3
    - 构建与依赖：Maven 多模块工程、JDK 17
2.2 架构形态
    - 后端采用三层架构（Controller -> Service -> Mapper/Repository），模块间通过 Maven 依赖组合。
    - web 模块拆分为 web-app（租客端）与 web-admin（运营端），两者共享 common、model。
    - 对外暴露 RESTful 接口，前端通过 HTTPS 调用；JWT 用于身份认证。
    - Redis 提供验证码、会话及热点缓存；MinIO 存储图片/附件；阿里云短信负责验证码发送；DeepSeek 模型通过 Spring AI 提供智能问答接口。
2.3 部署拓扑
    - 推荐将 web-app 与 web-admin 独立部署成两个 Spring Boot 服务，分别监听 8081、8080 端口。
    - MySQL、Redis、MinIO 部署在内网，阿里云短信/DeepSeek 为外部服务。

3. 模块设计
3.1 父工程（lease）
    - 统一管理依赖版本及构建配置，聚合 common、model、web 模块。
3.2 common 模块
    - constant：业务常量（RedisConstant 等）。
    - exception/result：统一异常、错误码与返回体。
    - login：LoginUserHolder 提供线程上下文内 JWT 解析结果。
    - minio/redis/sms：封装外部服务（MinIO、Redis、短信）组件。
    - utils：通用工具（JwtUtil、VerifyCodeUtil）。
    - 提供基础配置、切面、拦截器（如有）供子模块复用。
3.3 model 模块
    - entity：数据库实体类，对应 MyBatis-Plus 表映射。
    - enums：业务枚举（BaseStatus、房源状态、账单状态等）。
    - vo/dto（如有）：接口视图对象，与前端交互使用。
3.4 web 模块
    - web-app：租客端服务
        - controller.*：按业务域划分，如 `login`、`apartment`、`room`、`agreement` 等。
        - service & service.impl：承载业务逻辑，调用 mapper、common 工具。
        - mapper：继承 MyBatis-Plus BaseMapper，实现数据库访问。
        - config：框架配置（MyBatisPlusConfig、异步任务、Knife4j 设置）。
        - resources: application.yml、mapper XML、自定义配置。
        - 入口类 `AppWebApplication` 启用异步任务（@EnableAsync）。
    - web-admin：管理端服务
        - controller.*：分为 apartment、lease、system、user 等目录。
        - service & mapper 结构与租客端类似，但包含更多运营管理场景。
        - schedule：定时任务（EnableScheduling）。
        - config/custom：全局配置、异常处理、认证拦截器等。
        - resources: application.yml、Mapper XML、静态资源（如有）。
        - 入口类 `AdminWebApplication` 启用定时任务。

4. 核心业务流程设计
4.1 租客登录
    - Controller：`/app/login/getCode` 获取短信验证码，`/app/login` 登录。
    - Service：调用阿里云短信服务发送验证码，Redis 控制频率与 TTL；登录时校验验证码、自动创建用户、生成 JWT。
    - Mapper：`UserInfoMapper` 查询/新增租客信息。
4.2 房源浏览
    - 房源列表按区域、公寓筛选；RoomController 提供详情查询接口。
    - Mapper 层通过 MyBatis-Plus 查询房间、标签、费用等关联表。
4.3 预约与合同
    - 租客端提交预约信息，后台审核；合同信息通过 LeaseAgreementController 暴露。
4.4 后台运营
    - 管理端维护公寓、房源、租期、标签等数据；
    - 定时任务生成账单、检查租约状态；
    - 文件上传通过 MinIO 客户端统一处理。
4.5 AI 咨询（可选）
    - Spring AI 配置 DeepSeek 模型，提供对话式接口（controller/springai 目录）。

5. 数据设计
5.1 主要实体
    - SystemUser（管理员账号）、UserInfo（租客信息）
    - Apartment、Room、RoomLabel、RoomAttr、Facility
    - LeaseAgreement、LeaseTerm、LeaseOrder、PaymentType、Bill
    - RegionInfo（省/市/区层级）
5.2 数据库设计原则
    - 使用 MyBatis-Plus 默认命名映射，下划线转驼峰；
    - 关键字段加索引（phone、apartment_id、room_id、agreement_id）；
    - 软删除/状态字段通过枚举维护（BaseStatus）。
5.3 配置
    - HikariCP 作为连接池，参数在 application.yml 配置。

6. 接口与协议设计
6.1 REST 规范
    - 基础路径：租客端 `/app/**`，管理端 `/admin/**`（参考 Controller 定义）。
    - 请求与响应：JSON，统一使用 Result<T> 包装（code/message/data）。
    - 错误码：ResultCodeEnum 定义业务错误码与描述。
6.2 鉴权
    - 租客端：JWT Token（Authorization: Bearer xxx），LoginUserHolder 解析并注入线程上下文。
    - 管理端：账号密码 + 图形验证码登录，后续可扩展权限控制。
6.3 文档
    - 使用 Knife4j/OpenAPI 自动生成接口文档（需在配置中启用）。

7. 安全设计
    - 敏感信息（数据库、Redis、API Key）通过环境变量或配置中心注入，不在仓库明文存放。
    - Redis 验证码设置重发间隔与过期时间，防止暴力破解。
    - 前端与后端通信使用 HTTPS，后端启用 XSS/CSRF 基础防护。
    - JWT 设置有效期与刷新机制（规划中），支持账号禁用校验。
    - 文件上传校验 MIME 类型与大小，公网访问通过 CDN 或签名 URL。

8. 性能与扩展设计
    - Redis 缓存热点房源、验证码等高频数据，减少数据库压力。
    - 结合 MyBatis-Plus 分页查询、LambdaQueryWrapper 构造动态条件。
    - 服务无状态，支持横向扩容；异步任务用于短信发送、消息推送。
    - 预留消息队列（后续可接入 RocketMQ/Kafka）处理高并发操作。

9. 配置管理
    - application.yml 为开发环境示例，建议按环境拆分（application-dev.yml 等）。
    - 使用 Spring Profiles 控制不同环境配置（数据库、Redis、MinIO、AI Keys）。
    - 命名规范：租客端配置由 `APP_` 前缀区分，后台配置由 `ADMIN_` 区分（建议）。

10. 部署与运维设计
    - 构建：`mvn clean package -pl web/web-app -am` 或对应模块打包。
    - 部署：可使用 Docker 镜像或传统 Jar 运行，需提前部署 MySQL、Redis、MinIO。
    - 监控：引入 Spring Boot Actuator 暴露健康检查、指标；结合 Prometheus/Grafana、ELK。
    - 日志：使用 Logback，分模块输出；记录关键操作与错误日志。

11. 测试策略
    - 单元测试：Service、Utils 层编写 JUnit/Mockito 用例。
    - 集成测试：对核心接口编写 Spring Boot Test，覆盖登录、房源查询、租约流程。
    - 接口测试：结合 Postman/Apifox，验证 Rest API 与文档一致性。
    - 性能测试：使用 JMeter/Locust，对登录、房源列表、合同生成等接口压测。

12. 风险与技术债
    - 敏感配置当前存在明文示例，需要迁移至安全配置管理。
    - 缺少统一权限与菜单管理体系，后续需引入 RBAC。
    - AI 模块属于试验性特性，需要稳定性评估与成本控制。
    - 文件上传相关安全策略需完善（病毒扫描、CDN 分发等）。

13. 未来扩展建议
    - 引入支付渠道接口，支持线上支付及分期。
    - 搭建消息通知中心，实现短信、邮件、站内信统一推送。
    - 构建 BI 报表与大屏，实现运营指标可视化。
    - 引入多租户架构，支持不同公寓品牌共享平台。

14. 附录
    - 环境依赖：JDK 17、Maven 3.9+、MySQL 8.x、Redis 6.x、MinIO 8.x、Docker（可选）。
    - 命名约定：包名小写、类名帕斯卡命名、常量全大写，下划线分隔。
    - 代码风格：遵循阿里巴巴 Java 开发手册（或项目约定）。
