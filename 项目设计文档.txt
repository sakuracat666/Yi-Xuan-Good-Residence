1. 系统总体设计
================================================================================

1.1 系统定位

    易选好寓是一套面向长租公寓业务的全流程运营管理平台，采用前后端分离架构，
    后端提供两套独立的Spring Boot服务：管理端（web-admin）和租客端（web-app），
    分别服务于公寓管理员和租客用户。

1.2 设计原则

    - 分层架构：Controller → Service → Mapper，职责清晰
    - 统一规范：统一返回格式、统一异常处理、统一枚举管理
    - 最小依赖：业务模块仅依赖common和model，模块间无直接依赖
    - 逻辑删除：所有实体均使用is_deleted字段实现软删除
    - 自动化：利用MyBatis-Plus的自动填充、分页、逻辑删除等能力减少样板代码

1.3 系统上下文

3. 模块划分与职责
================================================================================

3.1 common 模块

    职责：提供被多个模块共享复用的基础能力
    ┌───────────────────────┬──────────────────────────────────────────────┐
    │ 组件                  │ 说明                                         │
    ├───────────────────────┼──────────────────────────────────────────────┤
    │ Result<T>             │ 全局统一返回结果封装（code/message/data）     │
    │ ResultCodeEnum        │ 返回状态码枚举（200成功，各类错误码）         │
    │ LeaseException        │ 自定义业务异常                                │
    │ GlobalExceptionHandler│ @ControllerAdvice全局异常拦截器               │
    │ JwtUtil               │ JWT创建/解析，HS256签名，10小时有效期         │
    │ LoginUser             │ 登录用户信息封装（userId/username/userType）  │
    │ LoginUserHolder       │ ThreadLocal存储当前线程登录用户               │
    │ RedisConfiguration    │ Redis序列化配置（String Key + Java Value）    │
    │ RedisConstant         │ Redis Key前缀和TTL常量                       │
    │ MinioConfiguration    │ MinIO客户端Bean配置                         │
    │ MinioProperties       │ MinIO连接参数（@ConfigurationProperties）     │
    │ AliyunSmsConfiguration│ 阿里云短信客户端配置                          │
    │ AliyunSMSProperties   │ 阿里云短信参数                                │
    │ MybatisPlusConfiguration│ MyBatis-Plus分页插件配置                    │
    │ MybatisMetaObjectHandler│ createTime/updateTime自动填充              │
    │ VerifyCodeUtil        │ 图形验证码生成工具                            │
    └───────────────────────┴──────────────────────────────────────────────┘

3.2 model 模块

    职责：定义数据模型，被common和web模块共享

    实体类继承关系：
    BaseEntity（id, createTime, updateTime, isDeleted）
    ├── ApartmentInfo（公寓信息）
    ├── RoomInfo（房间信息）
    ├── LeaseAgreement（租约）
    ├── UserInfo（租客用户）
    ├── SystemUser（系统用户）
    ├── PaymentOrder（支付订单）
    ├── RentBill（租金账单）
    ├── RepairRequest（报修请求）
    └── ... （共39个实体类）

    枚举类设计：
    所有枚举实现BaseEnum接口，使用@EnumValue注解标注数据库存储值，
    MyBatis-Plus通过default-enum-type-handler自动完成枚举与数据库值的转换。

3.3 web-admin 模块

    职责：管理端后端服务，端口8081
    核心功能域：
    - 公寓与房间管理（CRUD + 发布状态 + 关联数据维护）
    - 基础配置管理（属性、配套、杂费、标签、租期、支付方式）
    - 租约管理（创建、审核、状态流转）
    - 预约看房管理（列表、状态更新）
    - 报修管理（指派、进度、状态）
    - 支付订单管理（查询、关闭、手动确认）
    - 用户管理（租客管理、后台用户管理、岗位管理）
    - 租户画像管理

3.4 web-app 模块

    职责：租客端后端服务，端口8082
    核心功能域：
    - 登录认证（手机号 + 短信验证码）
    - 房源浏览（公寓、房间详情查询，条件筛选）
    - 预约看房（创建预约、查看列表）
    - 租约管理（查看、确认、退租、续约）
    - 账单管理（查看账单列表、当前应付）
    - 支付功能（统一支付、多支付渠道、退款）
    - 报修管理（提交、查看、撤销）
    - 个人中心（收藏、浏览历史、资料编辑）
    - AI对话助手（DeepSeek集成，Function Calling）

6.4 公寓保存逻辑

    保存/更新公寓时采用事务操作，在保存apartment_info主表后：
    1. 删除原有apartment_facility关联 → 批量插入新关联
    2. 删除原有apartment_label关联 → 批量插入新关联
    3. 删除原有apartment_fee_value关联 → 批量插入新关联

6.5 房间保存逻辑

    保存/更新房间时采用事务操作，在保存room_info主表后：
    1. 删除原有room_attr_value关联 → 批量插入新关联
    2. 删除原有room_facility关联 → 批量插入新关联
    3. 删除原有room_label关联 → 批量插入新关联
    4. 删除原有graph_info（房间图片）→ 批量插入新图片
    5. 删除原有room_lease_term关联 → 批量插入新关联
    6. 删除原有room_payment_type关联 → 批量插入新关联

6.6 统一支付逻辑

    支付预览：
    1. 根据租约获取待支付账单（押金 + 租金）
    2. 计算建议支付金额（deposit + rent）
    3. 返回可选支付方式列表

    支付执行：
    1. 根据pay_method_combination判断支付模式
    2. 创建PaymentOrder（主订单）
    3. 创建PaymentDetail（支付明细，按渠道拆分金额）
    4. 调用对应支付渠道完成支付
    5. 支付回调处理：更新明细状态 → 更新订单状态 → 更新账单状态

    退款逻辑：
    1. 查询原支付订单和支付明细
    2. 按原支付渠道原路退回
    3. 创建RefundRecord记录退款信息
    4. 支持部分退款（余额 + 微信混合退款）

6.7 AI对话助手逻辑（FunctionController）

    采用Spring AI的ChatClient构建对话能力：
    1. 系统提示词定义AI角色和能力边界
    2. Function Calling注册查询函数（公寓信息、房间信息、设施配套等）
    3. 会话记忆：使用ChatMemory实现上下文连续对话
    4. 位置感知：根据用户浏览记录推断用户偏好
    5. 流式响应：使用Flux<ChatResponse>实现逐字输出

7. 安全设计
================================================================================

7.1 认证机制

    管理端：
    1. 请求图形验证码 → 生成验证码 → 存储Redis（key前缀 + UUID，TTL 60秒）
    2. 提交用户名 + 密码 + 验证码key + 验证码value
    3. 校验验证码 → 校验用户名/密码 → 生成JWT Token → 存储Redis（TTL 10小时）
    4. 返回Token

    租客端：
    1. 请求短信验证码 → 生成6位数字 → 存储Redis（key前缀 + 手机号，TTL 10分钟）
       → 调用阿里云SMS发送
    2. 提交手机号 + 验证码
    3. 校验验证码 → 校验手机号存在 → 生成JWT Token → 存储Redis（TTL 10小时）
    4. 返回Token

7.2 授权机制

    - 接口拦截器验证Header中的Authorization Bearer Token
    - 从Token中解析用户信息 → 查询Redis验证Token有效性
    - 将LoginUser存入LoginUserHolder（ThreadLocal），供业务层获取当前用户

7.3 数据安全

    - 管理端密码：MD5加密存储
    - 逻辑删除：所有删除操作更新is_deleted字段，不物理删除
    - 乐观锁：user_balance表使用version字段防止并发更新
    - 数据隔离：租客端接口通过LoginUserHolder获取当前用户ID，仅能操作自己的数据

8. 公共组件设计
================================================================================

8.1 统一返回封装（Result<T>）

    public class Result<T> {
        private Integer code;     // 状态码
        private String message;   // 提示信息
        private T data;           // 业务数据

        public static <T> Result<T> ok(T data);
        public static <T> Result<T> ok();
        public static <T> Result<T> fail(ResultCodeEnum resultCodeEnum);
        public static <T> Result<T> fail(Integer code, String message);
    }

8.2 全局异常处理（GlobalExceptionHandler）

    @RestControllerAdvice
    - 捕获 LeaseException（业务异常）→ 返回对应ResultCodeEnum
    - 捕获 Exception（系统异常）→ 返回通用错误信息

8.3 MyBatis-Plus配置

    分页插件：MybatisPlusConfiguration 注册 MybatisPlusInterceptor + PaginationInnerInterceptor
    自动填充：MybatisMetaObjectHandler 在insertFill时自动设置createTime和updateTime，
              在updateFill时自动设置updateTime
    枚举处理：通过default-enum-type-handler配置，自动将@EnumValue标注的字段值与数据库互转
    逻辑删除：BaseEntity的isDeleted字段使用@TableLogic注解

8.4 Redis Key设计

    管理端验证码：admin:login:captcha:{captchaKey}，TTL 60秒
    租客端验证码：app:login:code:{phone}，TTL 10分钟
    管理端Token：admin:login:token:{token}，TTL 10小时
    租客端Token：app:login:token:{token}，TTL 10小时
